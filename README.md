## 🏗 Архітектура та Бази Даних

Система складається з двох Python-мікросервісів (FastAPI), спільного шару доступу до даних (DAL) та трьох різних NoSQL баз даних.

1. **MongoDB (Документна СУБД)**
   * **Роль:** Джерело правди (Source of Truth).
   * **Дані:** Зберігає детальні документи бажань користувачів (назви, посилання, теги) та знімки (snapshots) згенерованих рекомендацій.

2. **Neo4j (Графова СУБД)**
   * **Роль:** Аналітичний рушій для колаборативної фільтрації.
   * **Дані:** Зберігає лише структуру зв'язків `(User)-[:HAS]->(Wish)` на основі унікальних URL. Використовується для швидкого обчислення коефіцієнта подібності Жаккара (Jaccard Similarity).

3. **Redis (In-Memory Key-Value СУБД)**
   * **Роль:** Кешування (Cache-Aside Pattern).
   * **Дані:** Кешує вішлісти та готові рекомендації для миттєвої віддачі клієнту, знімаючи навантаження з основних баз.

## 🚀 Мікросервіси

* **`wishlist_api` (Port: 8080):** Керує життєвим циклом бажань (CRUD). При додаванні нового бажання сервіс зберігає документ у MongoDB, оновлює граф у Neo4j та інвалідує кеш у Redis.
* **`reco_api` (Port: 8081):** Шлюз рекомендацій. При запиті перевіряє кеш Redis. Якщо кеш порожній — делегує обчислення схожих користувачів графовій базі Neo4j, після чого "збагачує" отримані ID детальними даними з MongoDB.
